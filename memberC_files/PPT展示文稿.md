## 📄 第 3 页 — 两种技术路线

**标题**: 两条路：检索增强 vs 模型微调

**要点**:
- 📚 **路线 A — 检索增强生成 (RAG)**
  - 用大模型 + 外部知识库
  - 优势: 知识可随时更新
  - 劣势: 依赖检索质量，模型大、成本高

- 🎓 **路线 B — 监督微调 (SFT)**
  - 用小模型 + 领域数据训练
  - 优势: 推理快、成本低
  - 劣势: 知识固化、更新需重训

- ❓ **我们的问题**: 哪条路更好？还是两者结合？

**建议配图**: 两条路的分叉示意图

**演讲提示**: "一个像开卷考试——现场翻书找答案；一个像考前突击——把知识背下来。哪种方式更有效？"

## 📄 第 7 页 — 成员 C 工作: Agent 系统架构

**标题**: Agent 架构: 让两个工具"对话"

**核心设计**:

```
        用户问题
           │
    ┌──────▼──────┐
    │  AI Agent   │  ← smolagents Code-Agent
    │  (编排调度)  │
    └──┬──────┬───┘
       │      │
  ┌────▼──┐ ┌─▼──────┐
  │RAG检索│ │模型推理 │
  │(查资料)│ │(做诊断) │
  └───────┘ └────────┘
```

**Agent 工作方式**:
- Agent 分析问题 → 决定需要检索还是直接回答
- 如需检索: 先 RAG 查资料 → 再模型诊断
- 如直接: 微调模型直接生成答案

## 📄 第 11 页 — 核心发现深度分析

**标题**: 🔍 为什么微调模型更忠实？

**发现 1**: 微调忠实度领先 45.7%
- 原因: 知识已写入权重，生成时不受检索噪声影响
- RAG 检索到的文档可能不完美 → 模型"跑偏"

**发现 2**: 大模型相关性仅领先 1.6%
- 说明微调后的小模型"理解问题"能力已接近大模型
- 1.6% 的差距在误差范围内

**发现 3**: 效率与质量的最优解
```
       质量 ▲
            │   ● Pure SFT ← 最优帕累托点
            │       (快 + 准)
            │
            │        ● Hybrid (慢 + 中)
            │    ● Pure RAG (中 + 低)
            └──────────────▶ 速度
```

**建议配图**: 散点图（质量 vs 速度，三个点）

**演讲提示**: "微调为什么更强？想象你把知识背下来了，考试时直接写，不会被参考资料带偏。而 RAG 查到的资料如果不准确，反而会干扰判断。"

## 📄 第 13 页 — Hybrid Agent 优化方向

**标题**: Agent 为什么没赢？如何改进？

**当前问题**:
- ❌ 检索+推理两步走，增加了延迟
- ❌ 上下文拼接方式简单粗暴
- ❌ Agent 缺乏精细化判断（什么时候该检索？）

**改进方向**:
1. ✨ **智能检索决策**: 训练一个分类器判断问题是否需要检索
2. ✨ **多步推理**: 实现 ReAct 循环——检索 → 推理 → 再检索 → 再推理
3. ✨ **自检机制**: 模型生成答案后自我验证，不通过则重新检索
4. ✨ **上下文融合优化**: 使用更好的 prompt 模板引导模型利用检索信息

**建议配图**: ReAct 循环流程图

**演讲提示**: "Agent 效果不理想不代表思路错了。我们的检索策略和融合方式还有很大优化空间，这正是后续工作的方向。"
